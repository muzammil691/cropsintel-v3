## Why this cluster is a duplicate

All three task IDs in this cluster are the **same task IDs** that drove the prior cluster (`1778146192564`) and its postmortem sections:

- **`phase-1.6b-adela-docker-railway-deployment-config-rem2`** appears in row 4 of the prior ADR's Context table; it was finally accepted on its third remediation (`d8fa318`).
- **`phase-1-CLUSTER-investigation-1778146192564`** is the prior cluster investigation itself; its attempt-1 and attempt-2 audits are written up in two postmortem sections of `ADR-2026-05-07-verifier-cluster-failure.md`. Final acceptance: `bda82a1`.
- **`phase-1.00f1-verifier-spec-path-after-sync`** is the **fix follow-up** the prior ADR queued for Bug A. Its first audit failed because the Verifier service on Railway was running pre-fix `server.ts` (the canonical operational gate flagged in the prior ADR's first postmortem). It was eventually accepted on its second remediation (`18c62a5`) once the redeployed Verifier picked up the fix.

In short: this cluster fired on the chronologically older failures in Atlas's failure log, not on a new defect. By the time this trigger fired (after `8b1d42a atlas: queue phase-1-CLUSTER-investigation-1778147114729`), the underlying issues were already diagnosed in the prior ADR and the artefacts were already shipped.

## Verification that the prior fixes are in place

- **Bug A (path-resolution race)** — fixed at commit `7a339ce`. Verified present in `verifier/src/server.ts` (sync runs before `findTaskSpec`).
- **Bug B (Builder 0-file)** — handed off to agent-loop track. Out of scope for Verifier ADRs.
- **Bug C (parser `docs/` blind spot)** — surfaced in the prior ADR's attempt-2 postmortem. Two-line fix queued separately; **still applies to this very ADR's audit**, hence the spec edit accompanying this commit.

## Decision

**Close cluster `1778147114729` with no new code action.** The cluster is a duplicate trigger over already-diagnosed failures. All three follow-ups from the prior ADR remain the canonical action items:

1. `phase-1.00f1-verifier-spec-path-after-sync` — **shipped** (`18c62a5`).
2. Builder 0-file diagnosis — agent-loop track, open.
3. Verifier spec-parser `docs/` allowlist — verifier track, open.
4. Migration filename collision (`atlas_schema_complete.sql` ×2) — phase-1.10b2 follow-up, open.

No new follow-up tasks are spawned by this ADR. Per acceptance criterion 3, this is documented as no-action and the cluster is closed.
