## Root cause — Bug B with a new sub-pattern

This is the same **Bug B (Builder 0-file pattern)** flagged but deferred in `ADR-2026-05-07-verifier-cluster-failure.md`, now expressed in a particularly hard-to-recover form on the `phase-1.6e` lineage.

The underlying mechanic is specific:

1. The work the spec asks for — `adela/src/scheduler.ts`, `adela/src/index.ts`, `node-cron` in `adela/package.json` — was **already shipped in a non-task-spec commit, `1dd90dd`** (`feat: Adela scheduler & health server with ai-analyst job (phase-1.6e)`), with the docs symlinks added at `1b0e75d`. Both commits landed before the autonomous task `phase-1.6e-adela-scheduler-health-server-fix-4-of-5` was ever queued.
2. When the autonomous Builder picks up the spec, the Builder's per-file existence checks pass (the files are already on disk), so it concludes "task complete" and exits with no diff. The agent-loop log for `-rem2` reads verbatim: *"All gaps from the previous failure have been successfully addressed. The task is complete: scheduler.ts implemented, index.ts implemented, package.json updated, docs symlinks exist."*
3. The Builder commit therefore lands as a 0-file commit (just the spec rename + log file).
4. The Verifier audits `head_after = <Builder SHA>`. Programmatically, `files-exist` against the post-sync HEAD should pass (the files truly exist there — verified locally: `existsSync('adela/src/scheduler.ts')==true`, `existsSync('docs/master-plan.md')==true` via the symlink). The AI judges (`o3-judgment`, `gemini-2-5-pro`), however, are reading both the spec ("CREATE these files") and the *commit diff* (effectively empty), and concluding the work was not shipped *by this commit*. Their gap text — `"adela/src/scheduler.ts is missing"`, `"package.json unchanged; dependencies and scripts missing"`, plus a fabricated `package-json-deps` check name (not a real verifier check; no such file in `verifier/src/checks/` — `grep -r package-json-deps verifier/` returns zero hits) — is a structural false negative that fires whenever a spec's deliverables already exist outside the commit window the verifier is evaluating.
5. Atlas's auto-requeue then synthesizes a `-rem`, `-rem2`, `-rem3` chain from those gaps. Each remediation tells the Builder to "create scheduler.ts" — but the Builder, looking at the working tree, sees scheduler.ts already there and again does nothing. The loop is closed.

So Bug B here has two pieces:

- **B1** (already on the agent-loop track) — the Builder is allowed to commit 0 functional files and still report success.
- **B2 — new this cluster** — the AI judges treat "no diff" as "no implementation" even when `loadShippedCodeContext` has loaded the existing file content. The judge prompt asks "did the shipped code satisfy the spec" but the judges interpret "shipped code" as "diff", not as "post-state of files named in `spec.filesRequired`". This is the symmetric mirror of Bug C (parser blind spot for `docs/`): in Bug C, the judges had nothing to read because the parser hadn't surfaced the path; in B2, the parser surfaces the path correctly and the loader reads the file fresh, yet the judges still answer "missing" because the work was done in a prior commit.

The same B2 pattern is already visible on a fifth task (`phase-1-CLUSTER-investigation-1778153395522`, queued at `2d4780a` after this investigation began) and will recur for any task whose deliverable was completed by a developer-authored commit before its autonomous spec was queued.

## Decision

**Close cluster `1778152873297`** with no Verifier-side or agent-loop-side code change in this ADR (per acceptance criterion 2 — fixes ship as separate task specs).

The diagnosis recommends one new follow-up task, plus a re-emphasis of the existing Bug B owner.

## Follow-ups

1. **`phase-1.6e-adela-scheduler-health-server-fix-4-of-5-mark-shipped`** (new) — short manual task: move the `phase-1.6e-adela-scheduler-health-server-fix-4-of-5*` rem-chain spec files from `.agent/tasks/in-progress/` and `.agent/tasks/queued/` into `.agent/tasks/done/`, so the auto-requeue loop stops re-firing. The implementation already exists in `1dd90dd` + `1b0e75d`; the only outstanding action is taking the spec out of the queue. **Two-line resolution; no Verifier change.**
2. **Bug B1 (Builder 0-file pattern)** — open, agent-loop track. Recap recommendation: agent loop should reject any Builder commit whose diff stat is 0 functional files **unless** the spec is explicitly an investigation/ADR-only spec. The current third-cluster-today re-confirms it.
3. **Bug B2 (judges treat empty diff as missing implementation)** — new, verifier track. The fix is in the o3/Gemini judge prompts: distinguish "files named in `spec.filesRequired` are present in the loaded context" from "files were touched in this commit's diff". A spec-marker like `### Already-shipped (from prior commit <sha>)` would let the judges treat a no-diff outcome as pass when the loaded context shows the implementation. Two-prompt + one regression test.
4. **Migration filename collision** (`atlas_schema_complete.sql` ×2) — open, phase-1.10b2 follow-up. Unchanged.
5. **Conductor cluster dedupe** — open, conductor track. The existing recommendation (dedupe a new cluster against task IDs already cited in any closed ADR) wouldn't have caught this cluster — its task IDs are new — but the recommendation still stands.
