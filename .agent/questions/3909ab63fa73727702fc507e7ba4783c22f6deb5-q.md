## Evidence per gap

### 1. BatchDiagnoseToolbar.tsx:48,87,90,93 — "icon-only button" (high)

The four flagged buttons all have **visible text labels**:

```tsx
// line 48
<button type="button" onClick={onSelectAll} className={BTN} disabled={busy || total === 0}>
  Select all
</button>

// line 87
<button type="button" onClick={onDiscussAll} className={BTN} disabled={busy}>
  Discuss all ({selected})
</button>

// line 90
<button type="button" onClick={onCopyCcPrompt} className={BTN} disabled={busy}>
  Copy combined CC prompt
</button>

// line 93
<button type="button" onClick={onDismissAll} className={BTN} disabled={busy}>
  Dismiss all
</button>
```

These are NOT icon-only. Adding `aria-label` would only duplicate the visible text and produce verbose screen-reader output.

**Root cause:** `designer/src/checks/accessibility.ts:49` uses
`closesImmediately = /^\s*<\/button>/.test(afterTag) || /^\s*$/.test(afterTag)`.
The second condition fires whenever the opening `<button>` tag's `>` is the last character on its line — i.e., for *any* multi-line button. The check never looks at the following lines for visible text content.

### 2. BatchDiagnoseToolbar / AssignToTeamMenu / AssignmentRow — "no responsive prefixes" (medium)

These files use **`flex-wrap`** as the responsive primitive instead of explicit `sm:`/`md:`/`lg:` breakpoints. `flex-wrap` reflows on narrow viewports without any breakpoint annotation. AssignToTeamMenu also uses `max-w-[calc(100vw-2rem)]` which is viewport-relative.

**Root cause:** the current heuristic appears to grep for `sm:|md:|lg:` and ignore `flex-wrap` / `max-w-[calc(100vw-*)]` / `overflow-x-auto` as alternative responsive techniques. (Heuristic source not located in this repo — possibly in a non-checked-in path or generated upstream.)

### 3. AtlasTabBar.tsx:97 / CascadeChip.tsx:47 / CombinedDiagnosisCard.tsx:93,137 — "hover: without transition-" (low)

Every flagged line has `hover:*` classes. The corresponding `transition-colors duration-200` lives **in the same className expression** but more than one line away because the className is composed via:

- `className={cn(BTN, ...)}` where `const BTN = '... transition-colors duration-200'`
- `className={cn(base, ...)}` where `const base = '... transition-colors duration-200'`
- `className={cn(..., buttonFocus)}` where `const buttonFocus = 'transition-colors duration-200 ...'`

**Root cause:** `designer/src/checks/motion.ts:23` only inspects a 3-line window
`[lines[i-1], line, lines[i+1]]`. When the `hover:` is in line N and `transition-colors` is in line N±2 or further (e.g. on the const declaration above), the heuristic doesn't see it. It also doesn't follow `cn()` references to constants.
